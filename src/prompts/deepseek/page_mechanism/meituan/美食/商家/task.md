# 任务：采集美食商家的商品

## 入口检查

| 情况 | 动作 |
|---|---|
| 这是商家详情页 | 继续 |
| 目的地是广告、活动、优惠券或不相关页面 | 返回列表 |
| 商品区不可见 | 见下面"打开商品区" |

## 打开商品区

1. 商品已可见 → 不点任何标签或分类。
2. 商品区未激活 → 滚动前最多一次 `tap_in_page`，打开 `菜品` 或 `团购` 这类商品级标签页。
3. 进入商品区后绝不再点分类锚点——它们会跳过中间的商品。
4. 完全没有可见商品区时，先检查可见标签页；在把页面当作耗尽之前，打开最直接的那一个商品标签页。

## 训练与连续采集

1. 采集器训练成功并回到顶部后，从训练结果里取安全商品滑动坐标与确切的
   `normal_swipe_profile.change_threshold`。
2. 调用 `collect_continuously(x, y, change_threshold)`，阈值用上面取到的原值。
3. 该工具用长滑动遍历，并对不完整的行补短滑，无需逐步调用模型。
   - `attention_required`：先检查当前页面并解决问题再恢复；不要调高阈值掩盖异常。
   - `yielded`：遵循到达的用户指令。
4. 没有经过核验的正常滑动档案时，要求采集器采样正常的短滑与长滑；手动滑动工具仍可用于恢复。

## 完成判定

| 路径 | 判定 |
|---|---|
| 连续采集 | 返回 `status="completed"` 即完成，无需再调 `is_done` |
| 手动滑动 | 只在页面可能耗尽时调 `is_done`；`done=false` 表示还要继续 |

两者都要求：连续三次有效采集滑动都没有新增持久化条目。
仅仅"看到底部"不授权返回；`attention_required`、`yielded` 也不是完成信号。

`is_done.done` 为 false 时，继续滑动同一商品区域；任何新增的持久化条目都会重置空滑计数。等出现新的"可能结束"证据后再检查一次，不要中途切换标签页或分类。

## 返回

只有在 `collect_continuously.status="completed"` 或 `is_done.done=true` 之后，才
`navigate_back(next_path="meituan/美食")`。

## 不要做
- 不要点击会离开商家详情流程的推广、优惠券、广告、评价、推荐目标，除非它们是暴露商品区的唯一途径。
- 不要在采集尚未授权完成时切换标签页或分类。
