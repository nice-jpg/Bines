# 任务：采集外卖美食商家的商品

## 入口检查

按顺序判定，任何一条不满足就按对应动作处理：

| 情况 | 动作 |
|---|---|
| 这是从 `meituan/外卖/美食` 进入的商家详情页 | 继续 |
| 目的地是广告、活动页、优惠券页、独立商品页、空白页或不相关页面 | 返回列表，不要在这里纠缠 |
| 有弹窗遮挡 | 先用 `tap_in_page` 关闭，再继续 |
| 出现验证码或人机校验 | 走全局验证码流程：`authenticate_captcha` → 等用户 → `captcha_authenticated` → 核验 |

## 页面操作

1. 先用 `page_view` / `page_read` / `page_node` 识别安全控件与滚动区域；抽象视图不足时才截图。
2. 商品已可见 → 不点任何标签或分类。
3. 商品区未激活 → 滚动前最多一次 `tap_in_page`，打开 `菜品` 或 `团购` 这类商品级入口。
4. 绝不在进入商品区后点击左侧分类或分类锚点。

## 训练与连续采集

1. 采集器训练成功并回到顶部后，从训练结果里取安全商品滑动坐标与确切的
   `normal_swipe_profile.change_threshold`。
2. 调用 `collect_continuously(x, y, change_threshold)`，阈值用上面取到的原值。
3. 该工具用长滑动遍历，并对不完整的行补短滑，无需逐步调用模型。
   - `attention_required`：先检查当前页面并解决问题再恢复；不要调高阈值掩盖异常。
   - `yielded`：遵循到达的用户指令。
4. 没有经过核验的正常滑动档案时，要求采集器采样正常的短滑与长滑；手动滑动工具仍可用于恢复。

## 完成判定

| 路径 | 判定 |
|---|---|
| 连续采集 | 返回 `status="completed"` 即完成，无需再调 `is_done` |
| 手动滑动 | 只在页面可能耗尽时调 `is_done`；`done=false` 表示还要继续 |

两者都要求：连续三次有效采集滑动都没有新增持久化条目。
`attention_required`、`yielded` 都不是完成信号；仅仅"看到底部"也不授权返回。

手动恢复时，下列情况才值得检查是否耗尽：出现底部标记、滑动后没有明显移动、可见商品内容仍在重复。
`is_done.done` 为 false 时继续滑动同一商品面板；新增条目会重置空滑计数。

## 返回

只有在 `collect_continuously.status="completed"` 或 `is_done.done=true` 之后，才
`navigate_back(next_path="meituan/外卖/美食")`。

## 不要做
- 不要点击会离开商家详情流程的推广、优惠券、推荐目标，除非它们是暴露商品列表的唯一途径。
- 不要在采集尚未授权完成时返回列表。
