# 美团外卖美食商家页（`meituan/外卖/美食/商家`）

## 规范路径
- 当前页面：`meituan/外卖/美食/商家`。
- 上级列表：`meituan/外卖/美食`。
- 本手册适用于从该列表进入的**任意**具体商家；页面路径中永远不出现商家名称。

## 页面模型

| 区域 | 内容 |
|---|---|
| 上部 | 商家名称、评分、距离、配送/门店元信息、入口控件 |
| 中部 | 标签页、分类控件、筛选或推广区块 |
| 下部 | 商品/菜单区，可能是下列之一 |

商品区的三种常见形态：

1. **单列商品列表**：通常以"温馨提示：请适量点餐"开头。
2. **左分类 + 右商品**：左侧是分类栏（导航，不是商品），右侧是商品列表。
3. **标签页切换**：商品内容随所选标签变化。

此外还可能出现以行内形式介绍商品的广告区块。

商品卡片可能暴露：名称、价格、原价、折扣/促销价、销量文本、简短描述。
部分可见行是公告、政策、提醒或推广文本，不是可购买商品。

## 操作边界
- 采集区只看"温馨提示：请适量点餐"以下的内容；其上方的头部推荐和广告不属于商品。
- 商品已可见就不要点任何标签或分类。
- 只在商品区未激活时，用最多一次 `tap_in_page` 打开商品级入口（`菜品`、`团购` 这类）。
- 一旦开始滚动，绝不在左侧分类或分类锚点之间跳转——会跳过未采集的商品。

## 采集目标

商家字段：商家名称、评分、距离。
商品字段：商品名称、价格、原价、折扣价、月售。

名称、价格、销量可能被拆分在相邻的多个视图区域中；采集器用 COLLECT.md 的锚点标注和经截图确认的基线来校验 `run(view)`。

## Merchant Schema
```json
{
  "name": "",
  "rating": "",
  "distance": ""
}
```

这份商家资料由采集器从页面顶部的初始证据保存，不由 `run.agent.py` 返回，也不计入条目提取评分。
